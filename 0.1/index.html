  • Identifier: https://datalab-platform.com/capsule/0.1
  • Version: 0.1
  • Status: experimental; may change before version 1.0
  • Terms: https://datalab-platform.com/capsule/terms# (JSON-LD prefix dlc)
  • Extends: RO-Crate 1.3 and Process Run Crate 0.6
  • Reference implementation: DataLab-Capsule

Archive

A capsule is a ZIP archive with exactly two entries, stored without compression: ro-crate-metadata.json (the manifest) and workspace.h5 (a DataLab HDF5 workspace, provenance block /DataLab_Provenance included). Readers must refuse absolute paths, .., drive letters, backslashes, duplicate or unexpected entries, links and encrypted entries, and must check the SHA-256 and size of workspace.h5 against the manifest.

Manifest

The manifest is an RO-Crate 1.3 metadata document whose @context is ["https://w3id.org/ro/crate/1.3/context", {"dlc": "https://datalab-platform.com/capsule/terms#"}].

  • The root Dataset (./) has a name, a description, datePublished and a licence (an entity or a text). Its conformsTo lists Process Run Crate 0.6 and this profile. It contains workspace.h5 (hasPart), mentions every action and carries dlc:manifestFingerprint and dlc:workspaceId.
  • workspace.h5 is a File with encodingFormat application/x-hdf5, contentSize and sha256.
  • Each activity of the workspace ledger is a CreateAction, or an UpdateAction for an in-place recomputation. Its instrument lists a SoftwareApplication for the operation contract (dlc:operationId, dlc:contractVersion) when the activity is replayable, or for the informative implementation (no operation identifier) when it is opaque, plus one for the DataLab edition that ran it. object and result list its input and output states; because JSON-LD arrays are unordered, the roles are also given as dlc:RoleBinding entities with an explicit position (dlc:inputs, dlc:outputs). Parameters are PropertyValue entities (dlc:parameters) with a lossless dlc:jsonValue.
  • Each state is a CreativeWork with its object identifier, its fingerprint and, when present in workspace.h5, its HDF5 path (dlc:locator).
  • Each execution environment is a dlc:Environment whose softwareRequirements list the package versions.

Manifest fingerprint

dlc:manifestFingerprint is sha256: followed by the lowercase hexadecimal SHA-256 of the RFC 8785 (JCS) canonical JSON of the manifest, computed without the dlc:manifestFingerprint property itself.

State fingerprint datalab-signal-v1

The payload is the UTF-8 JCS form of {"scheme": "datalab-signal-v1", "dtype": "<f8", "length": N, "rows": ["x", "y"], "units": {"x": "s", "y": ""}} (little-endian NumPy dtype string, missing units as ""), one 0x00 byte, then each row (x, y, then dx and dy when present and not all NaN) as contiguous little-endian bytes. The value is sha256: followed by the lowercase hexadecimal digest of the payload.

State fingerprint datalab-image-v1

The payload is the UTF-8 JCS form of {"scheme": "datalab-image-v1", "dtype": "<u2", "shape": [ny, nx], "coords": {...}, "units": {"x": "mm", "y": "mm", "z": ""}}, where coords is {"uniform": {"x0": ..., "y0": ..., "dx": ..., "dy": ...}} or {"nonuniform": {"x": nx, "y": ny}}, one 0x00 byte, the data in C order as little-endian bytes, then, for non-uniform coordinates, the X and Y coordinates as little-endian float64. The value is sha256: followed by the lowercase hexadecimal digest of the payload.

Regions of interest

A state whose object has a region of interest records its definition (masks derive from it) and the sha256: digest of its RFC 8785 canonical JSON next to the fingerprint, which covers the data, coordinates and units only; the manifest shows the definition as dlc:roi. A state is the same only when both its fingerprint and its region of interest (or the absence of one) match: a saved object whose data are unchanged but whose region of interest differs is reported as altered.

Analysis results

An analysis result is an artifact stored under a key of its object. The artifact records the sha256: digest of the RFC 8785 canonical JSON of the stored value (arrays as nested lists, non-finite numbers as {"$float": "NaN" | "Infinity" | "-Infinity"}), shown as dlc:resultDigest. When a later analysis stores a different value under the same key, the earlier artifact is reported as replaced, never as the later value.

Legacy activities

A workspace saved without provenance may hold, in each processed object's metadata, a record of the processing that produced it. Such a record becomes an action with dlc:origin legacy_metadata, and nothing missing is invented: its inputs bind objects (dlc:objectUuid) whose state at execution time is unknown, it has no parameters, no environment and no edition, it is never replayable, and dlc:legacy keeps the record as stored with the issues found at import (missing ancestry, unavailable inputs, unsupported operations, version warnings, unreadable parameters, unidentified analysis results). It claims no result (result and dlc:outputs are empty): the state of the holding object observed when the workspace was opened is named by dlc:observedState, a state that no action produced, since the data may have changed after the processing without the record changing.
